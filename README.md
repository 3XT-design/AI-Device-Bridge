# AI Device Bridge

个人设备之间的文件交付工具，并正在加入单机视频动捕分析。当前版本支持设备配对、自然语言查找候选文件、人工审核传输计划、通过 HTTPS 发送文件，以及 M7 的视频深蹲分析基线。

## M7 验收候选版（1.1.0rc2）：视频深蹲分析与本机 AI 解读

“动作分析”页可打开摄像头或回放本地视频。将摄像头放在身体侧面并让全身进入画面后，程序在本机提取姿态关键点，识别下蹲、起身和完成次数，并在动作中显示躯干前倾与下蹲深度的初步提示。可以请求 15–60 FPS 采集，实际帧率取决于摄像头；采集线程持续读取画面，分析端只取最新帧。视频回放按源视频帧率进行，处理跟不上时跳过过期帧。勾选保存后，摄像头会在所选目录保存原始 MP4 和逐帧 CSV；视频回放只保存 CSV。默认不保存视频或分析记录。

界面显示读帧到界面的 p50/p95/p99 延迟、本帧推理时间、处理帧率和有效关键点比例。这些是本机软件侧指标，尚不包含摄像头传感器曝光到读帧的时间。姿态模型使用 MediaPipe 0.10.21 自带的离线模型，首次使用不需另行下载模型；M7 源码运行需要 Python 3.12。Windows 实机摄像头、30/60 FPS 和动作准确度验收见 [docs/M7-acceptance.md](docs/M7-acceptance.md)。

停止摄像头或视频回放后，如至少有 10 帧有效姿态，可点击“AI 分析本组动作”。程序把本组次数、角度、阶段和提示计数发给**本机** Ollama，生成简短观察和下一组建议，并显示耗时；不发送视频或逐帧关键点。模型名称沿用已保存的 AI 设置，也可在动作分析页修改。建议先用已经安装的模型；若 `qwen2.5:7b` 响应过慢，可尝试较小的 `qwen2.5:3b`。Ollama 不参与逐帧提示，动作中的反馈仍由本机姿态分析给出。

## v1.0.0 Windows x64

接收端只接受已配对设备的专用授权码；两台电脑需要**相互保存配对**。每次发送先提交文件名、大小、目标子目录和 SHA-256，接收电脑弹窗同意后才开始上传正文。拒绝、90 秒超时、轮换授权码或解除配对都会阻止未开始的上传。M5 及更早版本显示的全局接收码不再被正式节点接受；升级后，在接收电脑选中发送设备并复制新的专用码到发送电脑即可。旧数据库、证书、计划和已接收文件保留。

服务启动在后台执行，界面立即显示“正在启动”。Windows 构建脚本只生成 Inno Setup 安装包及 `SHA256SUMS.txt`；GitHub Actions 在 Windows 构建并检查打包后的 TLS 节点。正式版说明见 [docs/releases/v1.0.0.md](docs/releases/v1.0.0.md)，M6 的自动验收与用户确认的双机验收见 [docs/M6-acceptance.md](docs/M6-acceptance.md)。

## M5 验收候选版（0.5.0rc2）：易用性与维护

界面现在分为“设备与配对”“发送文件”“AI 查找”“历史与诊断”四页，每页保留自己的滚动位置。发送页可直接跳到设备页选择接收设备；AI 候选经人工确认保存为计划后，会自动打开发送页并选中该计划。

首次打开会显示双机配置步骤，关闭指引后不再自动显示。计划按钮和 AI 查找按钮通过悬停提示当前缺少的条件；“发送所选计划”继续显示原因。计划可按文件名、设备和状态搜索最近 500 条；发送和接收历史可按文件名、方向和状态搜索最近 2000 条，界面最多显示 100 条匹配结果。AI 地址和模型可单独保存。

“复制诊断信息”会提供版本、数据目录、数据库版本、服务状态和最近错误；日志位于 `%APPDATA%\AI Device Bridge\logs\bridge.log`，接收授权码、已保存的对端授权码与私钥会脱敏。请不要手工在反馈中粘贴授权码。可确认清理 30 天前已结束的传输历史；计划、设备、授权信息及磁盘文件保留。数据库采用 `PRAGMA user_version` 的逐步迁移，首次打开旧版数据库会自动升级。Windows 双机及安装器升级、卸载实测流程见 [docs/M5-acceptance.md](docs/M5-acceptance.md)。

## M4 验收候选版（0.4.0rc3）：可审核 AI 计划

在授权目录输入“把上周的报告.pdf发到台式机桌面”一类描述时，程序先扫描文件元数据，按明确的扩展名和日期条件筛选，再综合文件名、类型提示和时间挑选最多 200 个候选供 Ollama 排序。普通词语匹配不到文件名时不会直接把候选清零。设备名称只能对应已配对列表；不明确时必须在列表中重新选择。“桌面”只会建议接收端 `Received/桌面` 子目录，不会写入 Windows 系统桌面。“上周”按本地时区的上一完整自然周筛选；“最近修改的文件”按修改时间展示最新 5 个，不设 30 天截止日期。“最近下载的压缩包”优先召回 ZIP、RAR、7z 等压缩文件，并在 Windows 上按文件创建时间近似排序。界面显示扫描文件数及候选时间。

用户需逐一选择候选，审核真实设备与目标目录，确认保存计划，再单独确认发送。AI 计划保存原始描述、候选 ID 与相对路径、最终人工选择，不保存文件正文。Ollama 不可用时可显示本地匹配候选，也始终可以通过“选择文件”走手动流程。模型返回的未知 ID、路径或操作指令不会用于建立计划。M4 的 Windows 双机验收步骤见 [docs/M4-acceptance.md](docs/M4-acceptance.md)；用户已反馈 M4 功能可用。

## M3 验收候选版（0.3.0rc1）：可靠传输

发送端现在显示源文件校验、已发送字节数和接收端校验阶段；上传过程中可以取消。每次发送尝试都会保存独立的任务与历史，失败后可对同一已确认计划重新发送。重试会从头上传，不支持断点续传。应用异常退出后，未收到接收端完成确认的任务会显示为“结果未知”；重试前请先检查接收端文件，以免遇到同名冲突。接收端只有完整校验成功后才发布文件，磁盘空间不足会返回明确错误。

发送端和接收端从 M3 起保存逐笔历史；M3 当时使用全局接收授权码，M6 已将其替换为按设备授权和逐次确认。服务重启会清理本程序遗留的临时文件，并将未确认完成的接收记录标为结果未知。用户已反馈 M3 在两台 Windows 电脑上运行成功，并传输约 5 GB 文件；Windows 安装包和完整异常场景仍需单独验收。

双机验收时，用同版安装包在两台 Windows 电脑上依次检查：正常发送时进度增长且接收端哈希一致；发送大文件中途取消后接收端没有正式文件或残留的 `.part`；重新发送产生一条新的完成记录，重启应用后历史仍可见；断网或超时后界面不显示成功，先检查接收端再决定是否重试。最后用 1 GiB 文件比较两端 `Get-FileHash -Algorithm SHA256` 结果。

## 开发环境

### 双击启动源码包（Windows）

开发或排错时，将源码 ZIP 解压到一个新目录，然后双击解压目录最外层的 `Start-AI-Device-Bridge.bat`。它会自动找到项目，并在 `%LOCALAPPDATA%\AI-Device-Bridge\venv` 创建或复用虚拟环境，避免解压路径较长时 PySide6 安装失败；首次启动时需要已安装的 Python 3.12，并会安装依赖。启动期间保留的命令行窗口会显示安装或运行错误。给普通用户分发的是 Windows 安装包。

需要 Python 3.12。要从项目根目录建立开发环境，可在 PowerShell 运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\setup_windows.ps1
.\scripts\run_windows.ps1
```

检查代码：

```powershell
python -m pytest -q
python -m ruff check .
```

## 构建 Windows 安装包

在 Windows 电脑的项目根目录运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\build_windows_release.ps1
```

先安装 Inno Setup 6。脚本会使用 PyInstaller 打包应用，再由 Inno Setup 在 `release` 目录生成 `AI-Device-Bridge-Setup.exe` 和对应的 `SHA256SUMS.txt`。安装器以当前用户权限安装，不需要管理员权限。首次运行仍需允许 Windows 防火墙专用网络上的 TCP 8765 入站连接。

升级时关闭应用并运行新版安装器。用户数据库、本机 TLS 证书、设备授权码和接收文件保存在 `%APPDATA%\AI Device Bridge`，不会写入安装目录，也不会随卸载删除。升级到 M6 后必须重新复制每台接收设备生成的专用授权码。

## 双机演示流程

两台 Windows 电脑都运行同一版程序，并处于可以互相访问的局域网。

1. 两边启动应用并点击“启动本机服务”。接收电脑运行 `ipconfig`，记下局域网 IPv4 地址。
2. 两台电脑都在“设备与配对”页输入对端的 `IPv4:8765` 并检查设备。通过可信渠道逐字符核对双方 TLS 指纹，再**分别在两台电脑上**保存配对。
3. 接收电脑在已配对列表选中发送电脑，复制“所选设备接收授权码”；发送电脑选中接收设备，在“发送文件”页粘贴并保存该授权码。旧的全局接收码不能继续使用。
4. **手动文件演示：**选择一个普通文件，选中目标设备，计算 SHA-256，检查文件名、大小、目标设备和目录，再确认计划。
5. **AI 文件演示：**选择授权目录，输入包含文件条件和可选设备、目录的描述并查找候选。若 Ollama 不可用，可使用本地匹配候选或手动选择文件。核对候选、已配对设备与接收目录后载入；程序计算 SHA-256，并弹窗审核完整计划。确认后计划入列，发送仍需单独确认。
6. 在最近计划中选择要发送的计划并点击“发送所选计划”。接收电脑确认本次请求后开始上传；发送端收到接收端大小和 SHA-256 校验成功的响应后，才显示成功。
7. 接收文件位于 `%APPDATA%\AI Device Bridge\Received\<目标目录>`。接收端不覆盖同名文件。可以在计划列表中删除记录；删除不会移除本地源文件、接收文件或相关传输历史。

## 1 GiB 大文件验证

在发送电脑项目根目录创建一个 1 GiB 测试文件（约占用 1 GiB 磁盘空间）：

```powershell
python .\scripts\create_test_file.py
```

脚本会在下载目录生成 `ai-device-bridge-test-1GiB.bin`，并输出 SHA-256。按上面的手动流程将它发到另一台电脑，等待校验完成后，在发送端和接收端分别执行：

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\ai-device-bridge-test-1GiB.bin" -Algorithm SHA256
Get-FileHash "$env:APPDATA\AI Device Bridge\Received\AI Device Bridge Inbox\ai-device-bridge-test-1GiB.bin" -Algorithm SHA256
```

两个哈希必须一致。测试后可删除这两个测试文件释放磁盘空间。此验证应在目标两台 Windows 电脑上执行；自动化测试使用较小文件验证了同一 TLS 上传、授权、落盘与哈希校验路径。

## 安全与数据范围

- 首次信任通过人工比较 TLS 指纹建立。接收授权码按设备生成，持有码等同于该设备的接收权限；请通过可信渠道传递，怀疑泄露时在接收电脑上轮换或解除配对。
- AI 查找只扫描用户选择目录中的文件名和元数据，不读文件正文；最多向配置的 Ollama 服务发送 200 个候选的相对路径、文件名、大小、修改时间以及用户描述。配置远程 Ollama 时这些信息会离开本机。
- AI 只推荐授权目录清单里的候选 ID，用户仍需审核文件、已配对设备和接收目录并确认计划；AI 不会触发发送。AI 计划的描述与候选元数据保存在本机 SQLite，便于追踪人工选择。
- 目前仅支持可互访的局域网内单文件传输；不支持断点续传、文件夹同步、公网中继或自动覆盖同名文件。

## 项目结构

- `src/ai_device_bridge/`：桌面界面、节点 API、传输、AI 检索和 SQLite 仓储
- `tests/`：领域、API、仓储、AI 检索和双节点传输测试
- `scripts/`：Windows 开发、发布构建和大文件测试辅助脚本
- `installer/`：Inno Setup 安装器脚本
