# M7 视频深蹲分析：Windows 实机验收

## 准备

在两台电脑上分别安装相同的 M7 候选版。此阶段的分析在运行应用的电脑本机完成，不需要配对或启动文件接收服务。把摄像头固定在身体侧面，尽量与髋部同高，让头、躯干、膝和脚踝一直在画面里。画面中只保留一名运动者；先做数次缓慢的深蹲。

## 采集与即时反馈

1. 打开“动作分析”，摄像头编号先用 0、请求帧率 30 FPS，点击“启动摄像头”。确认预览和人体关键点出现；若摄像头打不开，尝试其他编号，并检查 Windows 摄像头权限与其他占用摄像头的程序。
2. 做 5 次缓慢深蹲，观察“下蹲中”“起身中”和次数显示是否与动作一致。在实际下蹲或起身期间观察姿态提示是否及时更新，记录明显误报或漏报。躯干提示使用侧面二维角度的初始阈值，深度提示使用髋膝相对高度，仅用于第一轮测量。
3. 勾选“保存本次分析记录”，选择本机文件夹，再做一组动作。停止后检查该文件夹中有 MP4 和 CSV。未勾选时不生成记录。CSV 对分析过的每帧记录源时间、读帧时间、推理耗时、动作阶段、角度、所选侧关键点和反馈；帧序号的间隔表示分析端跳过了旧画面。录像线程持续采集原始画面，MP4 使用摄像头报告的固定帧率；若设备实际帧率不稳定，以 CSV 中的读帧时间作时间分析依据。
4. 重复以上过程，请求 60 FPS。启动时显示设备报告帧率，停止后显示设备实测帧率；再比较“处理 FPS”、跳帧数和延迟。若处理明显落后，尝试 30 FPS。摄像头可以不支持 60 FPS，记录报告值和实测值。

## 回放与两机比较

1. 在笔记本和台式机上分别打开同一段已录好的深蹲视频，使用“打开视频回放”。回放按视频时间播放，推理跟不上时会跳过过期帧；结束后状态栏显示跳帧数。分别记录 p50/p95/p99、处理 FPS、有效关键点比例、动作次数。
2. 由人工观看原视频，标出每次下蹲开始、最低点、起身结束及明显躯干前倾的时间。用保存的 CSV 对照动作阶段、次数和提示；记录误报、漏报及提示发生时刻。无需拿模型输出当人工真值。
3. 使用同一摄像头位置、光照、衣着和距离分别录制 30 FPS 与 60 FPS 视频，再在两台电脑上回放比较。记录摄像头型号、实际分辨率、设备报告帧率、CPU/GPU 占用、处理 FPS 和提示延迟。

## 本机 Ollama 分析

1. 在运行应用的电脑上启动 Ollama，用 `ollama list` 查看已安装模型。动作分析页会读取先前保存的 Ollama 地址和模型名；如果模型名不同，在此页改成已安装的名称。地址应为 `http://127.0.0.1:11434`，动作分析只允许连接本机服务。
2. 做一组深蹲并点击“停止分析”，或回放一段深蹲视频。有效姿态帧至少 10 帧后，点击“AI 分析本组动作”。应看到观察、下一组建议、局限及 Ollama 耗时。核对模型描述是否只依据界面统计，尤其在次数为 0 时不能凭空声称完成了动作。按钮点击后仍应能操作界面。
3. 关闭 Ollama 再点击分析，应看到连接失败原因；打开 Ollama 后可重试。动作中的姿态提示在 Ollama 关闭时仍应正常显示。这里的 AI 解读在一组结束后产生，不能当作动作中实时纠正的延迟数据。

“读帧至界面”从 OpenCV 返回画面开始计时，包含姿态推理、绘制和界面交付，不包含摄像头曝光及驱动缓存，因此不能直接当作身体动作到屏幕提示的完整延迟。M7 的初始实验目标是 p95 低于 200 ms；是否适合实际运动中纠正姿态，需要结合人工标注的视频和主观体验判断。

## 构建安装包

在 Windows 项目根目录安装 Python 3.12 和 Inno Setup 6 后运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\build_windows_release.ps1
```

脚本只生成 `release\AI-Device-Bridge-Setup.exe` 和 `release\SHA256SUMS.txt`。安装包会包含 MediaPipe 的姿态模型；构建脚本中的 `--collect-all mediapipe` 用于把模型文件和运行数据一起打包。Windows CI 会执行文件服务和姿态模型两项打包后检查；仍需按本页在真实摄像头上验收。
