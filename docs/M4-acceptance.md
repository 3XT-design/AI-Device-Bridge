# M4 可审核 AI 计划验收（0.4.0rc2）

当前为源码候选版。Linux 环境已执行自动化测试；下表的 Windows 双机结果必须在用户电脑上填写，不能据此宣称安装包或双机已经通过。

## 准备

两台 Windows 电脑使用同版程序，保持 M3 的配对和授权码。发送端创建一个仅用于测试的授权目录，放入两份名称相近的报告、一份其他类型文件，以及一份位于目录外的文件。要验证“上周”，将测试文件的修改时间设在上一完整自然周。Ollama 可用时先测模型排序；之后停止 Ollama，测本地回退。源码 ZIP 解压后可双击 `Start-AI-Device-Bridge.bat`，它会使用短路径虚拟环境。

| 场景 | 通过条件 | Windows 结果 |
| --- | --- | --- |
| 文件条件 | “上周的报告.pdf”仅展示授权目录内、上周修改、扩展名匹配的候选；目录外文件不出现 | 待实测 |
| 最近文件 | “找最近修改的文件”按修改时间从新到旧展示；即使文件早于 30 天也不会被排除，界面显示扫描总数 | 待实测 |
| 多候选和无结果 | 多份候选停在人工选择；无结果提示修改描述，不生成计划 | 待实测 |
| 设备解析 | 描述中唯一匹配的已配对设备可供审核；未知或同名设备要求用户重新选择；解除配对后不能建立该目标计划 | 待实测 |
| 目录澄清 | “台式机桌面”明确显示为 `Received/桌面`，用户可改为其他安全子目录；绝对路径和 `..` 被拒 | 待实测 |
| 模型越权 | 模型返回不存在的候选 ID 或文本路径时不能生成对应文件计划 | 待实测 |
| Ollama 离线 | 本地匹配结果可供人工审核；手动选择文件仍可使用 | 待实测 |
| 审核与追踪 | AI 计划显示 AI 来源，保存描述、候选 ID/相对路径和人工选择；重启后记录仍在；未单独点击发送时没有传输 | 待实测 |
| 实际发送 | 审核计划后单独确认发送；接收端文件与源文件 SHA-256 相等 | 待实测 |

本候选版的意图解析是保守的规则解析，未识别出的设备或目录需要用户在界面中明确选择；模型只参与候选文件排序。接收端仍使用 M3 的全局接收授权码，不支持按文件在接收端逐次同意。
